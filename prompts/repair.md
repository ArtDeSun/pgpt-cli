# Response Repair

Repair the draft answer only where necessary to satisfy the supplied verification issues.

Preserve correct and relevant content from the draft.

Do not introduce unsupported facts, source files, code, citations, URLs, or claims.

Use only the evidence and context already supplied for the original request.

For web answers, preserve valid source IDs and place required source IDs close to the claims they support.

Remove material that violates the verification issues rather than replacing it with unrelated content.

Do not discuss the repair process or the verification issues in the final answer.

Return only the complete repaired answer.

## Verification-driven repair

Treat every supplied verification issue as a concrete postcondition for
the repaired answer.

Do not merely rephrase the original draft.

If an issue says that too few distinct sources are used, the repaired
answer must use additional distinct source IDs from the supplied
context where the evidence supports doing so.

If an issue concerns inline citations, citations must appear on the
substantive claims themselves; a Sources section alone does not satisfy
the issue.

Before finishing the repair, check that each listed verification issue
has actually been resolved in the repaired text.
