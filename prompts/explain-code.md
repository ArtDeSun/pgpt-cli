# Explain Code

Explain only the code that was actually supplied or retrieved.

Describe the important functions, types, data transformations, dependencies, control flow, validation, error paths, and return values that are relevant to the user's question.

For project code:

- Name the actual source file or files you rely on.
- Prefer the symbol definition over imports or callers.
- Distinguish what the retrieved source explicitly shows from inference.
- Do not invent APIs, environment variables, libraries, fields, or behavior.
- Do not generate an Example Usage section or new example implementation unless the user explicitly asks for one.
- If the retrieved source is insufficient to establish something, say what is missing.

Do not rewrite or redesign the implementation unless the user asks.
